# Perch的远程助手

Perch的远程助手为 macOS 和 Windows 提供账号设备直连、口令协助、键鼠控制、文件互传和文本分享。工作台左侧可选择设备或口令协助，右侧显示设备状态和操作。每次连接打开独立的远控窗口，可从设备详情或「会话窗口」切回。

## 启动发布版

| 平台 | 启动方式 |
| --- | --- |
| macOS 13 及以上，Apple 芯片或 Intel | 解压 `PerchRemote-macOS-universal.zip`，打开 `Perch的远程助手.app` |
| Windows x64 | 解压 `PerchRemote-Windows-x64.zip`，在解压后的 `PerchRemote` 文件夹中运行 `PerchRemote.exe` |

Windows 的程序和运行库随包提供，请从解压后的完整目录运行。macOS 0.4.4 起使用固定的自签名身份，适用于本地使用。首次从临时签名版切换时，先退出旧版，在「应用程序」中替换应用，再给新版开启「屏幕与系统录音」和「辅助功能」权限并重启应用。以后在同一位置替换使用同一签名身份的版本。macOS 包未通过 Apple 公证，Windows 包未签名。

关闭工作台、被控窗口或共享窗口会收进 Windows 系统托盘或 macOS 菜单栏，登录和现有会话继续运行。从托盘菜单选择「打开工作台」，再到「会话窗口」恢复其他窗口。主控端关闭远控窗口会结束该会话。要完全退出，从托盘菜单选择「退出」。

在「设置 → 界面外观」可选择森林绿、海雾蓝、暮霞紫、白色或深色主题。工作台与远控窗口同步切换，应用会记住本机的选择。

## 连接设备

账号使用邮箱登录，可选择密码或邮箱验证码。在「账号 → 注册」输入已获授权的邮箱，获取验证码并设置密码。验证码五分钟内有效。信令服务管理员邮箱由 `PEERDESK_ADMIN_EMAILS` 配置，支持逗号分隔的多个地址。管理员首次验证邮箱后，可在「账号 → 注册白名单」添加或移除授权邮箱。

升级后，已绑定邮箱的账号用邮箱重新登录即可查看原有设备。此前未绑定邮箱的旧账号需使用获授权的邮箱注册。移除白名单条目只影响该邮箱的注册资格，已注册账号仍可登录。

1. **账号直连**。两台电脑在同一个信令服务登录同一账号。完成系统授权的设备会自动提供直连，共享主屏幕和系统声音。主控端在左侧选择目标设备，再点击「连接」。Mac 锁屏时会维持直连，允许远程尝试输入解锁密码。休眠会结束当前会话，唤醒后可重新连接。使用紧急结束快捷键后，重新登录或启动可恢复本机直连。
2. **口令协助**。共享方登录账号后点击「共享屏幕」，创建邀请。异地协助使用「自建信令服务」，桌面端也支持受信任局域网中的 HTTP 信令地址。协助方登录账号后在工作台粘贴完整邀请，点击加入。共享方逐项允许观看和键鼠控制。邀请一次有效，有效期 10 分钟。
3. **结束会话**。在工作台的设备详情或会话列表点击「断开」，也可在远控窗口的控制中心选择「结束会话」。被控端可使用窗口内显示的紧急结束快捷键。协助方按 `Shift + Esc` 可退出画面的键盘焦点。

预配置的腾讯云版本可直接使用工作台中的默认服务器地址。所有会话都需要在桌面工作台登录账号后建立。

## 远控控制中心

主界面「设置 → 视频编码」可选择自动、H.264 或 H.265（HEVC）。改动在下次连接时生效。主控端选择了具体格式时优先使用该选择，主控端选择自动时可采用被控端指定的格式。H.265 需要双方支持相应的发送和接收能力。无法协商时先尝试 H.264，再由 WebRTC 协商可用格式。远控窗口的网络状态显示本次实际使用的编码和回退状态。

连接后，从主控窗口右上角打开「控制中心」。原画上限为 3840 × 2160 和 30 Mbps，超清为 2560 × 1440 和 14 Mbps，高清为 1920 × 1080 和 8 Mbps，默认标准为 1280 × 720 和 4 Mbps。画面保留宽高比，竖屏采用对应的宽高上限。实际分辨率和码率随源画面和网络负载变化。四档画质需要两端均使用 0.6.3 或更新版本。

开启「优先发送快捷键到被控端」后，聚焦远控画面时，主控客户端会优先转发收到的组合键。主控系统截留的组合可在下拉菜单中选择并发送，例如切换应用。按 Shift + Esc 可退出键盘焦点。

两端使用 0.6.3 或更新版本，且同账号会话取得 TURN 凭证后，可在「更多」开启「服务器中转加速」。切换会短暂重连媒体链路，选择关闭后恢复优先直连。网络状态显示实际选中的路径。

远控画面占满窗口内容区，保留原始宽高比，并随窗口尺寸调整。默认帧率上限为 60 Hz。负载较高时，编码优先保持帧率，画面可能暂时降低分辨率。

同账号直连默认共享系统声音。使用口令协助时，共享方可勾选「同时共享系统声音」。Mac 系统声音需要 macOS 14.2 或更高版本及系统录音权限。在控制中心可调主控播放音量。被控端允许键鼠控制后，可开启结束锁屏或被控端静音。关闭静音、被控端停止键鼠控制或结束会话时，应用会恢复被控端播放。 [Electron 桌面采集说明](https://www.electronjs.org/docs/latest/api/desktop-capturer/)

右下角的网络浮层显示连接路径、延迟、实际分辨率、帧率和视频码率。在控制中心的「更多」可切换浮层显示。使用画质和安全设置时，两端都需要支持控制中心的版本。

在控制中心的「更多 → 导出性能诊断」可保存 JSON 摘要，包含采集交接、编码、接收缓冲、解码、视频呈现间隔和输入分发回执统计。双方均支持新版诊断协议时，主控摘要会包含被控端阶段数据。输入回执测量到原生调用返回，应用处理输入及画面反馈可通过桌面实测核验。详细指标、复现实验和本轮结果见[远控流畅度优化开发文档](docs/remote-performance-optimization.md)。

原生采集跟随 30/60/90/144 Hz 设置。纹理交接忙碌时保留最新待处理画面，通道背压恢复后补发末尾鼠标坐标。输入侧为移动与可靠状态事件分别保留速率额度。

Mac 首次启动时，工作台会提示设置屏幕录制和辅助功能权限。屏幕录制权限用于分享画面，辅助功能权限用于被控端键鼠操作。授权后重启应用。macOS 15 及以上可在「隐私与安全性 → 本地网络」检查局域网访问权限。Windows 键鼠操作适用于当前用户可操作的普通窗口，管理员窗口、登录界面和 UAC 界面受 Windows 安全边界保护。 [Apple 本地网络说明](https://developer.apple.com/documentation/Technotes/tn3179-understanding-local-network-privacy) · [Microsoft SendInput 说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)

## 文件复制和粘贴

两台电脑使用 0.6.0 或更新的桌面客户端，并建立键鼠控制会话。在任一端的 Finder 或资源管理器选中普通文件，用 ⌘C 或 Ctrl+C 复制，然后在另一端的文件夹用 ⌘V 或 Ctrl+V 粘贴。从远端复制到本机时，等远控窗口提示「文件已就绪」后再粘贴。向远端粘贴时，保持目标文件夹聚焦，文件到达后会在目标电脑发起粘贴。若切换了目标窗口，按提示在目标文件夹再执行一次粘贴。

桌面文件按分块直接写盘，每次最多 128 个普通文件，单次合计上限 4 GiB。接收前会检查可用空间，并为其他文件保留 512 MiB。暂存文件在至少 24 小时后的应用启动时清理。浏览器或旧版本的文件互传使用原有选择文件入口，单文件上限 100 MiB。

## P2P 与异地部署

- **信令**使用 WebSocket。邀请有效期 10 分钟，每份邀请只容纳一个观看者。URL 片段包含随机会话密钥，客户端用它加密并认证 SDP 和 ICE 消息。信令服务持有房间标识和运行状态。网页客户端代码由部署者提供，因此双方都需要信任网页来源。
- **直连与回退**由 WebRTC ICE 选择。局域网可用 `host` 候选，STUN 提供 `srflx` 候选；获授权会话也会检查 TURN 候选，以便在直连不可用时使用中继。口令协助仅在双方登录账号都获当前信令服务管理员授权时提供 TURN。界面根据真实选中的 ICE 候选对标记路径，任一端是 `relay` 即标记为 TURN。网络中断时尝试有限次 ICE 重启，恢复连接后需要重新授予键鼠权限。
- **数据**通过 WebRTC 传输。视频走 SRTP。文本、按键和点击走可靠 DataChannel。双方使用新版客户端时，鼠标移动和拖动坐标走无重传通道，按下与松开保持可靠传输。桌面文件复制走独立通道，接收端确认写盘后继续接收。文件和视频不会经过信令服务器，选择中继时会以 WebRTC 加密流量经过 TURN。
- **会话结束**会关闭连接、停止抓屏并释放远程按下的键鼠。信令连接中断或本机休眠也会结束会话。Mac 锁屏会维持会话，以支持远程输入解锁密码。

当前预配置的腾讯云入口使用 TCP 8443 提供账号服务和信令，地址探测使用公共 STUN。账号直连的信令密钥由信令服务生成，服务部署者因此属于该会话的信任边界。口令协助的会话密钥由客户端生成。画面、键鼠和文件走 P2P。部署外置 TURN 后，满足账号授权条件的会话可在打洞失败时走中继。 [腾讯云轻量部署](deploy/tencent/README.md)

异地使用时，将 Node 服务放在 HTTPS 反向代理后面。代理应保留原始 Host 并转发 WebSocket 升级。例如使用 Caddy：

```caddy
assist.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

以下 Node 配置使用外置 TURN。将示例域名和共享密钥换成部署值。

```sh
STUN_URLS='stun:turn.example.com:3478' \
TURN_URLS='turn:turn.example.com:3478?transport=udp,turn:turn.example.com:3478?transport=tcp,turns:turn.example.com:5349?transport=tcp' \
TURN_SHARED_SECRET='<coturn REST 共享密钥>' \
npm start
```

coturn 使用 REST 模式。以下字段与上方示例配套，公网服务器需配置证书及放行监听和中继端口。管理员可在工作台的「服务器中转授权」中授予已注册账号使用权限。服务端签发有效期为一小时的 TURN 凭证，并在活动会话中续签。口令协助双方均须获授权才会收到凭证。撤销授权会结束该账号现有的 PeerDesk 会话，并阻止其建立新的中继会话。

```ini
realm=turn.example.com
fingerprint
use-auth-secret
static-auth-secret=<coturn REST 共享密钥>
listening-port=3478
tls-listening-port=5349
min-port=49160
max-port=49200
cert=/path/to/fullchain.pem
pkey=/path/to/privkey.pem
no-cli
no-multicast-peers
user-quota=4
total-quota=128
```

按部署环境限制 TURN 的可达目标，公网实例应阻止对私网和链路本地地址的中继。如果 TURN 位于一对一 NAT 后，额外配置 coturn 的 `external-ip` 和端口映射。获授权账号的会话可使用中继。REST 凭证一小时失效，活动会话会自动续签。托管服务的静态 `TURN_EXTERNAL_USERNAME` 和 `TURN_EXTERNAL_CREDENTIAL` 凭证有效期由服务商决定，撤销授权不会使其提前失效，需要在服务商处轮换。 [WebRTC 连接指南](https://webrtc.org/getting-started/peer-connections) · [coturn 配置](https://github.com/coturn/coturn/blob/master/examples/etc/turnserver.conf)

## 源码构建与验证

运行自建信令服务需要 Node.js 22.13 或更高版本。打包需 macOS、Xcode Command Line Tools 和 Go，产物写入 `releases/`。

```sh
npm ci
npm test
npm run test:e2e
npm run test:workspace
npm run test:performance
npm run mac:signing:init  # 仅首次建立本地签名身份
npm run package
```

本地签名身份保存在打包用户的 `~/Library/Application Support/PerchRemote Signing/identity.pem`，文件只允许当前用户访问。后续 macOS 发布版须复用同一文件，迁移打包机器时一并安全迁移。

端到端测试使用生成的画面源，建立真实 WebRTC 会话并比较文件字节。工作台测试覆盖邮箱注册、白名单管理、两台设备同时连接和单独断开。为 `test:workspace` 提供 TURN 环境变量并设置 `TEST_TURN=1`，测试会通过管理员授权测试账号后验证账号设备中继。浏览器用例可通过 `CHROME_BIN` 指定 Chromium。为 `test:e2e` 设置 `TEST_NATIVE=1 TEST_DIRECT_DESKTOP=1`，并通过 `PEERDESK_MAC_EXE` 指定打包后的可执行文件，可验证 Mac 客户端本机回环。Windows 原生输入组件可在 `desktop/wininput` 目录运行 `go test ./...`。

## UU 远程对照

本地安装的 UU 远程是 macOS 4.40.0（构建 621），应用包为 x86_64 / arm64 双架构。其 `libstreamer.dylib` 的 arm64 导出符号包含 WebRTC 类型、主控端 `CreateOffer`、被控端 `CreateAnswer`，以及双方的 `IceServers`、`AddCandidate` 和 `SetRemoteSdp`。这些符号表明该构建包含 WebRTC/ICE 的会话协商代码。链接信息还显示 ScreenCaptureKit、VideoToolbox、AudioToolbox、Network 和 GameController 依赖。线上信令格式、各条路径的使用条件、TURN 节点和选择策略仍未确认。本项目使用公开标准实现独立信令和传输，不与 UU 客户端互通。功能依据来自 [网易官网](https://uuyc163.net/)、[使用帮助](https://uuyc163.net/help/index.html)、[Mac 被控说明](https://uuyc163.net/features/mac/index.html)和[文件传输说明](https://uuyc163.net/help/20241210/40220_1199229.html)。
